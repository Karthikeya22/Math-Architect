# Lock figures to shared math specs

**The preferred way to keep quiz images synchronized with questions—especially when math correctness matters—is to drive stem text, keyed answer, figure, and explanation from one structured parametric source of truth, then render the figure with a deterministic engine (SVG templates, Graphie-style APIs, GeoGebra/Desmos/JSXGraph state), not with free-form text-to-image.** Production edtech and assessment systems already do this: Khan Academy authors Graphie constructions that become PNGs; Desmos and GeoGebra embeds share calculator or construction state with the item; Numbas binds diagram parameters to question variables; Pearson and College Board treat graphics as versioned SVG/vector assets with alt and long descriptions that must match the stem ([Khan Graphing API](https://github.com/Khan/khan-exercises/wiki/Graphing-API); [Desmos API](https://www.desmos.com/api?lang=enpersonal); [Numbas extensions](https://docs.numbas.org.uk/en/latest/extensions/first-party.html); [Pearson TestNav media](https://support.testnav.com/as/include-audio%2C-video-or-images-143491334.html)). Recent 2025–2026 methods that improve faithfulness—layout-conditioned diffusion, LayoutGPT→GLIGEN, and vision-LLM critique loops—still cannot guarantee exact counts, equal fractional parts, or labeled geometry; benchmarks show T2I counting collapsing as object counts rise and MathGen’s best closed models near **~42%** overall under script judges ([GeckoNum](https://arxiv.org/html/2406.14774); [MathGen](https://arxiv.org/abs/2603.27959); [TIFA](https://arxiv.org/html/2303.11897v3)). Florida B.E.S.T. Math Architect’s core flaw—images and explanations drifting from the stem—is therefore an architecture problem, not a prompt-tuning problem: the product’s brief→raster→vision path matches a common hybrid *attempt* but is the wrong primary path for assessment-grade B.E.S.T. visuals. The fix is to expand typed `visualSpec` / GeoGebra / SVG renderers for countable and geometric families, demote diffusion to non-constraint illustration, gate publish with structured checklists and Learning Commons Graphics Accuracy, and regenerate explanations from the same locked claim as the figure.

## Platforms bind stems to engines, not to prompts

Serious math platforms treat stem–visual sync as an authoring-system property. Khan Academy editors draw with a Graphie API (`path`, `circle`, `label`, `plot`) inside `div.graphie`; graphs can update from shared IDs, and engineering practice retains the generation source even when the classroom sees a pre-rendered PNG for load speed ([Khan Graphing API](https://github.com/Khan/khan-exercises/wiki/Graphing-API); [Khan engineer reply on Graphie sources](https://www.reddit.com/r/Khan/comments/2155sp/graphs_not_as_pictures/)). Interactive Khan graphs later moved from Raphael SVG to Mafs React components while remaining **typed graph families** (linear, circle, polygon), not sampled bitmaps ([Khan accessibility rebuild summary](https://briefly.co/anchor/Online_learning/story/rebuilding-graphs-for-accessibility-inside-khan-academys-inclusive-design)). Desmos exposes `setState` / `setExpression` and screenshot to PNG or SVG so the displayed figure is calculator state; Classroom and Amplify Activity Builder co-locate graph exhibits with notes and inputs, and DigitalEd Möbius locks Desmos state in feedback and gradebook modes so the figure cannot drift from the authored item ([Desmos API](https://www.desmos.com/api?lang=enpersonal); [Desmos Graph Exhibits](https://blog.desmos.com/articles/new-features-in-activity-builder/); [Möbius HTML examples](https://www.digitaled.com/support/help/admin/Content/INST-AUTHORING/AUTHORING-EXAMPLES/HTML-examples.htm)). GeoGebra materials embed as configured constructions; Inspera and similar LMS partners paste embed codes so candidates see the author’s geometry ([GeoGebra Material Embedding](https://geogebra.github.io/docs/reference/en/Material_Embedding_(Iframe)/); [Inspera GeoGebra help](https://support.inspera.com/hc/en-us/articles/360036554091-How-to-use-GeoGebra-as-an-embed-code)). Open assessment tool Numbas makes the contract explicit: GeoGebra and JSXGraph constructions pull values from **question variables** and link objects to student inputs; Eukleides generates illustrations with auto descriptions—correctness is guaranteed by construction when variables are correct, not by model sampling ([Numbas first-party extensions](https://docs.numbas.org.uk/en/latest/extensions/first-party.html)).

Curriculum and high-stakes banks reinforce the same pattern. Illustrative Mathematics–style figures appear as CMS assets with detailed alt text; MathemaTikZ retains **3,793** unique IM diagrams each with problem context and TikZ implementations, evidence that open-curriculum graphics are vector/programmatic assets ([AccessIM glossary](https://accessim.org/6-8/grade-6/glossary?a=teacher); [MathemaTikZ](https://doi.org/10.1145/3698205.3729558)). Pearson Assessment Systems recommend **svg/svgz** (and png/tiff) uploads into shared media repositories; Graphic Gap Match requires populated dimensions, alt text, and precise coordinates; ACT and College Board Bluebook require alt text and long descriptions that convey every essential visual detail ([Pearson TestNav media](https://support.testnav.com/as/include-audio%2C-video-or-images-143491334.html); [ACT VPAT](https://www.act.org/content/dam/act/unsecured/documents/act-state-and-district-VPAT-2025.pdf); [Bluebook JAWS / image descriptions](https://bluebook.collegeboard.org/students/accommodations-assistive-technology/jaws); [NWEA Image Description Guidelines](https://www.nwea.org/uploads/2022/11/Image-Description-Guidelines-for-Assessments_NWEA_2021.pdf)). Classroom game platforms diverge: Quizizz and Kahoot largely use teacher uploads or stock search, and when they care about graph correctness they add a **parameterized graph maker**, not a diffusion model; Kahoot’s AI image feature carries explicit accuracy disclaimers and leaves responsibility with the author ([Quizizz Graphing question type](https://quizizz.com/home/en/graphing-question); [Kahoot AI image generation](https://support.kahoot.com/hc/en-us/articles/40991497959187-How-to-generate-images-with-AI)). No primary source claims production high-stakes quiz rasters stay mathematically correct without human verification; the closest research “success” for AI visuals is structured code generation (TikZ/SVG) with human-enhanced specs, and even then MathemaTikZ’s best published success rate is **73.9%**—still a **~26%** residual failure rate incompatible with unattended banks ([MathemaTikZ](https://doi.org/10.1145/3698205.3729558); [Math-Vision Diagrams](https://arxiv.org/html/2608.08964v1)).

## Diffusion cannot own counts; 2025–2026 methods compile then verify

Compositional T2I evaluation repeatedly isolates the failure modes that break quiz figures. TIFA finds models struggle with **counting, spatial relations, and multi-object composition**; GenEval reports position and attribute binding remaining weak even as overall scores rise; GeckoNum shows exact object counts limited to small numbers and deteriorating with each successive count, with fractions and part–whole among the hardest tasks ([TIFA](https://arxiv.org/html/2303.11897v3); [GenEval](https://arxiv.org/abs/2310.11513); [GeckoNum](https://arxiv.org/html/2406.14774)). T2ICountBench argues prompt refinement generally does **not** fix counting; E2V-Bench finds quantity errors in **90.4%** of coded failures and shows a structured DSL/icon renderer achieving near-perfect accuracy on the same early-arithmetic visuals where closed T2I models fall from roughly **50%** to **20–25%** as counts move from 1–5 to 6–10 objects ([T2ICountBench](https://www.alphaxiv.org/abs/2503.06884); [E2V-Bench](https://arxiv.org/html/2605.31212)). MathGen (2026) places best closed-source T2I near **42.0%** overall under Script-as-a-Judge verifiers, with function/plane domains far worse ([MathGen](https://arxiv.org/abs/2603.27959)). An ablation that swaps SVG intermediates for DALL·E 3 on math hint diagrams yields “not useful” figures with wrong counts and unintended 3D look, while SVG pipelines approach ground-truth VQA scores—Khan and IXL already standardize on SVG for problems and hints ([From Text to Visuals](https://arxiv.org/html/2503.07429)).

The accurate recent methods therefore sit on a different ladder than prettier diffusion. Layout-conditioned systems (LayoutDiffusion, ControlNet, T2I-Adapter, LayoutGPT→GLIGEN) improve approximate placement—LayoutGPT claims **20–40%** gains on numerical/spatial correctness versus end-to-end T2I—but still generate pixels without algebraic guarantees ([LayoutGPT](https://layoutgpt.github.io/); [GLIGEN](https://openaccess.thecvf.com/content/CVPR2023/papers/Li_GLIGEN_Open-Set_Grounded_Text-to-Image_Generation_CVPR_2023_paper.pdf); [ControlNet++](https://arxiv.org/html/2404.07987v3)). Stronger 2025–2026 patterns are **diagram-as-program**: AutomaTikZ and MathemaTikZ emit TikZ and compile; Geometry DSL and Straightedge compile high-level constructions to exact SVG and refuse or flag invalid claims; Pelican exposes spatial predicates and `verify()`; Draw2Think and GeoGebra MCP / SketchMath have an LLM issue typed commands into a constraint engine, then Propose–Draw–Verify with engine errors and retries ([AutomaTikZ](https://arxiv.org/abs/2310.00367); [geometry-dsl](https://github.com/shand001/geometry-dsl); [straightedge](https://pypi.org/project/straightedge/); [Draw2Think](https://arxiv.org/pdf/2605.20743); [SketchMath](https://github.com/dadadadas111/SketchMath)). Render-in-the-Loop and similar SVG self-feedback loops improve layout by inspecting cumulative canvases; DiagramIR shows intermediate representations plus deterministic validators agree with humans better than LLM-as-a-Judge alone ([Render-in-the-Loop](https://arxiv.org/html/2604.20730v2); [DiagramIR](https://doi.org/10.48550/arxiv.2511.08283)). Vision critique loops (Self-Refine, Idea2Img, Maestro, IPR) help when they emit **structured defects and corrective edit signals**, treat hard constraints as pass/fail gates, and keep the incumbent best via pairwise comparison—but OpenAI’s image-eval cookbook and practitioner guides still insist that models that cannot pass count/text gates need a **workflow change**, not only more paraphrases ([Maestro](https://arxiv.org/html/2509.10704); [OpenAI Image Evals](https://developers.openai.com/cookbook/examples/multimodal/image_evals); [SC LABS verify guide](https://sclabs.uk/guides/verify-ai-generated-images-with-vision-model/)). Learning Commons **Graphics Accuracy** (released October 14, 2026) specializes this for classroom math: describe with exact claim-dependent counts, derive an answer from the image independent of the claimed answer, then compare—fail-closed, with Correction/Defects/Errors for repair—and is best used as a second-opinion gate beside deterministic renderers, not as a replacement for them ([Graphics Accuracy](https://docs.learningcommons.org/evaluators/graphics-evaluators/graphics-accuracy)).

## Exactness ranks code renderers first, diffusion last

When mathematical exactness beats aesthetics, the consensus ranking is unambiguous. **Typed DSL or templates → programmatic SVG** (or icon layout) scores highest on correctness for K–12 countable visuals, with medium polish and medium React implementation cost—E2V’s DSL path is near-perfect where T2I collapses ([E2V-Bench](https://arxiv.org/html/2605.31212)). **GeoGebra / Desmos / JSXGraph command or state → render/export** matches assessment practice on the digital SAT (embedded Desmos), STACK scoring, and Möbius items, with medium–high polish and higher integration cost ([Bluebook Testing Tools](https://bluebook.collegeboard.org/students/tools); [STACK GeoGebra](https://docs.stack-assessment.org/en/Specialist_tools/GeoGebra/GeoGebra/); [Desmos commercial API plans](https://help.desmos.com/hc/en-us/articles/49078363315725-API-Plans-for-Commercial-Use)). Constraint languages such as Asymptote or carefully validated TikZ deliver print-quality vectors but raise toolchain latency. **LLM → SVG/TikZ/GeoGebra + compile + IR verify** is the right *AI* pattern when schemas are narrow and retries are bounded—MathemaTikZ’s **73.9%** ceiling shows open-ended codegen still needs templates and gates ([MathemaTikZ](https://doi.org/10.1145/3698205.3729558)). Manim remains strong for instructional video and heavy for per-item CBT latency. **Figure brief → T2I + vision verify** ranks last on correctness despite highest polish: GeckoNum, MathGen, T2ICountBench, and the SVG-vs-DALL·E ablation all argue against it as the primary path for stem-critical figures ([GeckoNum](https://arxiv.org/html/2406.14774); [MathGen](https://arxiv.org/abs/2603.27959); [From Text to Visuals](https://arxiv.org/html/2503.07429)).

“Beautify” in an exactness-first stack means CSS/SVG theming or constrained style after geometry is locked—not img2img that reintroduces sampling noise. AIBench notes that logic and aesthetics are hard to optimize simultaneously and that SVG-first planning yields near-perfect logical topology even when dense diagrams look cluttered; its multi-level VQA for logic correlates with human experts at Spearman **ρ = 0.886** versus **0.600** for coarse VLM scoring ([AIBench](https://www.alphaxiv.org/overview/2603.28068)). Product QA should therefore decouple logic from aesthetics and prefer **fact checks against a structured visual spec** (expected counts, bar lengths, coordinate points, axis ranges) over CLIPScore or a single “looks good” score ([T2I-CompBench](https://proceedings.neurips.cc/paper_files/paper/2023/file/f8ad010cdd9143dbb0e9308c093aff24-Paper-Datasets_and_Benchmarks.pdf); [OpenAI Image Evals](https://developers.openai.com/cookbook/examples/multimodal/image_evals)). Controllable diffusion remains acceptable only when the image is contextual illustration that does **not** encode the keyed quantity—and even then a VLM check should reject contradictory counts.

## Math Architect should resync from one claim, not regenerate pretty wrong art

Math Architect’s documented mainline figure path—illustration brief → gpt-image render → vision verify with a small retry budget, then client fallback to deterministic SVG or no figure—is the right *loop shape* on the wrong *renderer* for B.E.S.T. elementary and geometry families where answers depend on exact counts, ten-frames, fraction models, number lines, or coordinate constructions. Earlier product research already concluded that Learning Commons Graphics Accuracy should complement (not replace) in-house vision verify, and that Anatomy/SVG deterministic paths must remain authority for registry-bound visuals; this sync research sharpens that into an operational cutover. The main flaw—figures and explanations that do not match the question—occurs when stem, answer key, raster, and remedial copy are produced as loosely coupled LLM generations rather than projections of one locked claim. GenAI MCQ studies show a related failure: stems that refer to a “given figure” without attaching one, or that cannot correctly use complex lesson figures ([Educ. Sci. 2025](https://www.mdpi.com/2227-7102/15/2/144)). Silent semantic errors (looks like math, teaches the wrong quantity) are worse than aesthetic defects because teachers may publish them.

The repair playbook that matches industry and 2026 research, ranked by reliability, is representation change first. Derive a **FigureBrief / must-show checklist** from stem plus keyed answer—exact counts, labeled lengths, axis ranges, distractor objects, accessibility longdesc draft—and make that brief the contract for both the image prompt and the judge (TIFA/DSG-style atomic yes/no questions; Learning Commons `composeGraphicsAccuracyClaim(question, answer)`) ([TIFA](https://arxiv.org/html/2303.11897v3); [DSG](https://arxiv.org/html/2310.18235v4); [Graphics Accuracy](https://docs.learningcommons.org/evaluators/graphics-evaluators/graphics-accuracy)). **Route by mechanism**: if the checklist requires exact math, render with typed `visualSpec` → programmatic SVG (counts, ten-frames, fraction bars/circles, number lines, part–whole) or GeoGebra commands for coordinate/geometry constructions already foreshadowed in-repo; allow AI raster only for non-constraining decoration. **Generate from the brief**, not from free prose alone. **Judge** with programmatic assertions where possible (count/label/axis checks modeled on DiagramIR/E2V), then VLM checklist and/or Graphics Accuracy; treat Unverified/uncertain as fail-to-publish, not as soft pass ([Graphics Accuracy](https://docs.learningcommons.org/evaluators/graphics-evaluators/graphics-accuracy); [SC LABS](https://sclabs.uk/guides/verify-ai-generated-images-with-vision-model/)). **Repair** with correction-conditioned regenerate (one defect class per attempt, budget **1–3** tries, keep-best among candidates), then path-switch to SVG/GeoGebra, then teacher queue—never ship Contradicted as if Supported. **Regenerate explanations and remedial copy from the same locked claim** after the figure passes, so walkthroughs cannot invent different counts than the stem or the graphic. Monitor production Error tags after model or prompt changes, as Learning Commons production-monitoring guidance recommends for evaluator-backed pipelines ([Monitor quality in production](https://learningcommons.org/resources/monitor-quality-in-production/)).

Concrete adoption order for the React/Express product: expand schema-driven SVG for the highest-volume B.E.S.T. visual families first; harden the GeoGebra command path for constructions; demote brief→image→vision to unsupported families or decorative contexts with hard reject (no silent wrong figure); add Graphics Accuracy beside the existing vision verifier for remaining rasters; keep Math Standards Alignment as a separate gate for learning-component coverage rather than conflating it with figure fidelity. Prefer sharing one structured payload between stem generation, figure render, and explanation so the figure cannot drift—the same coupling E2V uses when equation maps to `{item, count, grouping}` before layout ([E2V-Bench](https://arxiv.org/html/2605.31212)). What remains uncertain is the exact latency/cost of always-on dual judges on every item and head-to-head GeoGebra headless export timing in this app; those are product measurements, not reasons to keep diffusion as the correctness path.

## Conclusion

The industry’s “strict sync” secret is boring on purpose: shared variables and compilable geometry beat clever prompts. Once that is accepted, Math Architect’s image–question mismatch stops looking like an LLM quality gap and starts looking like a misplaced bet on raster sampling for a domain where wrong counts invalidate the item. The durable upgrade is to make the structured claim the product’s spine—render it, verify it, explain it—so Florida teachers publish figures that are correct by construction rather than correct by hopeful retry.
